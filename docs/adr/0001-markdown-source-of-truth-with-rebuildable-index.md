# Markdown 书稿目录为事实源，索引可重建

Status: accepted

采用「Markdown 书稿目录为创作内容事实源、结构化索引（better-sqlite3）为可重建派生数据」的存储架构，并消除 JSON/Markdown 运行时双写。理由：支持多设备按文件同步、内容可被任意工具读取与 diff、索引损坏可整体重建。

考虑过的选项：纯 JSON 文件（现状，双写不一致风险）、单一 SQLite 文件为事实源（同步冲突、二进制不可读）、MD 事实源 + SQLite 索引（选定）。

后果：编辑器写路径改为以书稿目录为主，索引允许滞后；现有 JSON 数据需一次性迁移（迁移前强制全量备份）。
